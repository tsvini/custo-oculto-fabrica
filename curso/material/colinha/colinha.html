3A receita de um teste

describe('Login', () => {          // o caderno de receitas
  beforeEach(() => {                // roda antes de CADA it
    cy.visit('https://www.saucedemo.com')
  })

  it('entra com usuário e senha', () => {  // uma receita
    cy.get('[data-test="username"]').type('standard_user')
    cy.get('[data-test="password"]').type('secret_sauce')
    cy.get('[data-test="login-button"]').click()
    cy.contains('Products').should('be.visible')  // a conferência
  })
})
Todo teste é assim:
1. abre o site (visit)
2. acha o elemento (get)
3. faz alguma coisa (type, click)
4. confere o resultado (should)

Sem o should, o teste só clica: ele não confere nada.

4Comandos do Cypress

cy.visit(url)abre o site cy.get(seletor)acha um elemento na página .type('texto')digita num campo .click()clica cy.contains('texto')acha pelo texto que aparece .select('valor')escolhe opção de um menu .first()pega só o primeiro da lista .should(...)confere (a asserção)

5As conferências (should)

'be.visible'está aparecendo na tela 'contain', 'txt'tem esse texto no meio 'have.text', 'txt'o texto é exatamente esse 'not.exist'não existe na página 'have.value', 'x'o campo tem esse valor 'be.disabled'o botão está desativado

O Cypress espera sozinho (até 4 segundos) a conferência dar certo. Não precisa de espera.

6Qual seletor usar? (aula 13)

1º MELHORdata-test[data-test="username"]feito pra testes: não muda quando o visual muda
2ºid#user-nameo "CPF" do elemento: não se repete na página
3º SE PRECISARclasse ou texto.btncy.contains('Login')muda fácil, o teste quebra à toa

Como achar: botão direito no elemento › Inspecionar. Abriu um monte de código? Clique na setinha no canto do painel (Ctrl + Shift + C) e depois no elemento. Ou, no Cypress, clique na mira (Selector Playground), passe o mouse no elemento e copie o seletor que ele sugere.

10Glossário: as palavras do dia a dia

QA: quem cuida da qualidade do sistema, testando antes de chegar no cliente Teste manual: uma pessoa usa o sistema e confere tudo na mão Teste automatizado: um código faz os passos e confere sozinho E2E: de ponta a ponta, usa o sistema como um usuário de verdade Spec: um arquivo de teste (o seu login.cy.js) Asserção: a conferência do teste, o should Seletor: o "endereço" de um elemento na página Runner: a janela do Cypress que mostra os passos e o site Teste negativo: testar o que acontece quando o usuário erra Regressão: rodar tudo de novo pra ver se nada quebrou Bug: o sistema fazendo algo diferente do esperado CI: testes rodando sozinhos sempre que o código muda Repositório: a pasta do projeto guardada no GitHub Commit: um "save" do projeto, com nome e data
