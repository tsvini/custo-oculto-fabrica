Todo arquivo de teste termina em .spec.js, é assim que o Playwright sabe que é teste.

3A receita de um teste

import { test, expect } from '@playwright/test';

test.describe('Login', () => {          // o caderno de receitas
  test.beforeEach(async ({ page }) => {  // roda antes de CADA teste
    await page.goto('/');
  });

  test('entra com usuário e senha', async ({ page }) => {
    await page.getByTestId('username').fill('standard_user');
    await page.getByTestId('password').fill('secret_sauce');
    await page.getByTestId('login-button').click();
    await expect(page.getByTestId('title')).toHaveText('Products');
  });
});
Todo teste é assim:
1. abre o site (goto)
2. acha o elemento (getBy…)
3. faz alguma coisa (fill, click)
4. confere o resultado (expect)

await = "espera esse passo terminar".
Esqueceu o await? O teste fica estranho e falha sem motivo.

4Ações

page.goto(url)abre o site .fill('texto')digita num campo (apaga o que tinha) .click()clica .selectOption('valor')escolhe opção de um menu .check()marca uma caixinha .press('Enter')aperta uma tecla .first()pega só o primeiro da lista

5As conferências (expect)

toBeVisible()está aparecendo na tela toHaveText('txt')o texto é esse toContainText('txt')tem esse texto no meio toHaveURL(/inventory/)a página é essa toHaveCount(2)tem essa quantidade toHaveValue('x')o campo tem esse valor not.toBeVisible()o contrário de qualquer um

O Playwright espera sozinho (até 5 segundos) o elemento aparecer e a conferência dar certo. Não precisa de "sleep".

6Como achar o elemento (aulas 17 e 18)

1º MELHORgetByTestIdgetByTestId('username')feito pra testes: não muda quando o visual muda. No saucedemo, configure testIdAttribute: 'data-test'
1º TAMBÉMgetByRolegetByRole('button', { name: 'Login' })acha como uma pessoa acharia: pelo papel e pelo nome
2ºtexto ou rótulogetByText('Products')getByLabel('Email')bom pra textos que não mudam

EVITE  locator('div:nth-child(3) > button'): depende da posição na página. Mudou o layout, o teste quebra à toa.

9O playwright.config.js que a gente monta (aulas 23 e 24)

import dotenv from 'dotenv';  // lê o arquivo .env (usuário e senha fora do código)
dotenv.config({ path: path.resolve(__dirname, '.env') });

export default defineConfig({
  use: {
    baseURL: 'https://www.saucedemo.com',   // aí o goto('/') já sabe o site
    testIdAttribute: 'data-test',             // o getByTestId procura data-test
    trace: 'on-first-retry',  screenshot: 'only-on-failure',  video: 'retain-on-failure',
  },
});

13Glossário: as palavras do dia a dia

QA: quem cuida da qualidade do sistema, testando antes de chegar no cliente E2E: de ponta a ponta, usa o sistema como um usuário de verdade Spec: um arquivo de teste (o seu login.spec.js) Locator: o "endereço" de um elemento na página Asserção: a conferência do teste, o expect Headless: navegador rodando sem janela, mais rápido Projeto (project): um navegador ou aparelho configurado no config Flaky: teste instável, às vezes passa, às vezes falha Trace: a gravação passo a passo de um teste CI: testes rodando sozinhos sempre que o código muda API: a porta dos fundos do sistema, que conversa por dados Regressão: rodar tudo de novo pra ver se nada quebrou
