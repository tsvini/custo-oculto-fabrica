# Roteiros aprovados · Módulo 12 (gerado do roteiro_playwright_m12.py)

## Aula 81: Veio do Cypress? Um mapa das ideias
1. Se você já usou Cypress, várias ideias vão parecer familiares. Mas não pense no Playwright como uma simples troca de comandos. [bigtext]
2. Algumas aproximações ajudam: cy ponto visit lembra page ponto goto. cy ponto contains lembra get by text. should lembra expect. [traducao]
3. Mas o modelo muda. No Playwright você escreve await em cada passo, e os seletores são objetos que você guarda e reaproveita. [bloco_vs]
4. As duas ferramentas resolvem problemas parecidos, com abordagens diferentes. Saber as duas te deixa mais forte no mercado. [bigtext]
5. Te vejo na próxima! [endcard]

## Aula 82: O seu projeto no currículo e na entrevista
1. Agora você tem um projeto de automação. Vamos colocar isso no seu currículo do jeito certo. [bigtext]
2. No currículo, escreve o que você realmente fez: testes de ponta a ponta com Playwright e JavaScript, Page Object, testes de API, vários navegadores e execução no GitHub Actions. [traducao]
3. A regra: só coloca o que você consegue explicar numa entrevista. [bigtext]
4. Perguntas que costumam aparecer e que você já sabe responder: o que é auto-wait? Por que preferir seletores pela função? O que é Page Object? [cards]
5. E o que é um teste flaky, que às vezes passa e às vezes falha? E como evitar? [cards]
6. Mostrar o projeto funcionando no GitHub ajuda muito a transformar o que está no currículo numa demonstração concreta. [gh_actions]
7. Te vejo na última aula! [endcard]

## Aula 83: Seu projeto pronto pro portfólio e a colinha completa
1. Última aula. Vamos deixar o seu projeto pronto pra quem visitar. [bigtext]
2. Cria um README ponto md com: o objetivo, as tecnologias, o que precisa instalar, como instalar, e os comandos pra rodar os testes. [editor]
3. Coloca o selinho do GitHub Actions. O próprio GitHub gera o código dele, com o endereço do seu repositório e do seu workflow. [editor]
4. Ele mostra se os testes estão passando. [github]
5. E a sua colinha completa: do primeiro comando ao Page Object, [tela]
6. ao login salvo, ao GitHub Actions e à API. Deixa ela aberta enquanto pratica. [tela]
7. Você começou sem saber nada e terminou com um projeto completo: login, compra, API e tudo rodando no GitHub. [cards]
8. Próximos passos: pratique, crie novos cenários e mantenha o seu GitHub atualizado. [cards]
9. E se o curso te ajudou, deixa uma avaliação honesta na Udemy. Ela ajuda a melhorar o curso e orienta outros alunos. [bigtext]
10. Até a próxima! [endcard]
