## Aula 22: describe e beforeEach
1. O seu arquivo vai crescer. Hoje você aprende a deixar ele organizado. [bigtext]
2. Antes, apaga aquele teste do usuário lento. Ele era só pra você ver a espera automática. [editor]
3. Agora vamos criar um segundo teste. O saucedemo tem um usuário que não consegue entrar: o usuário bloqueado, locked underline out underline user. [tela]
4. Escreve o teste novo embaixo do primeiro. Ele preenche o usuário bloqueado e espera ver a mensagem locked out. [editor]
5. Repara: a linha do goto se repete nos dois testes. [editor]
6. Quando algo se repete antes de todo teste, existe o before each. Before each: antes de cada. [traducao]
7. Coloca o goto lá dentro, e apaga dos testes. [editor]
8. Agora o describe. Describe é descrever: ele junta testes do mesmo assunto numa caixa com nome. [traducao]
9. Tudo que está dentro desse describe é sobre login. [editor]
10. Lendo em português: um grupo chamado Login. Antes de cada teste, abra o site. Teste um: entra. Teste dois: mostra erro pro bloqueado. [cards]
11. Roda: os dois passam. [editor]
12. E no relatório eles aparecem juntos, debaixo de Login. [pw_relatorio]
13. Na próxima aula: o arquivo de configuração. [passo]
14. Te vejo lá! [endcard]

## Aula 23: playwright.config - baseURL e data-test
1. Hoje a gente mexe no arquivo de configuração. Parece assustador, mas são só duas linhas. [bigtext]
2. Abre o playwright ponto config ponto js e procura o use. Use quer dizer: use isso em todos os testes. [editor]
3. Tira o comentário da baseURL e coloca o endereço do saucedemo. Base URL: o endereço base. [editor]
4. Agora, no teste, o goto fica só com uma barra. O Playwright junta essa barra com o endereço base. [editor]
5. A vantagem: se um dia o site mudar de endereço, você troca num lugar só. [cards]

## Aula 24: Variáveis de ambiente - tirando usuário e senha do código
1. Aqui no saucedemo o usuário e a senha são públicos. Mas em projeto de verdade, senha e chave escrita no código é um problema: quando o projeto for pro GitHub, todo mundo vê. [bigtext]
2. Então a gente vai aprender o jeito usado em projetos reais: um arquivo chamado ponto env, que guarda essas informações fora do código. [cards]
3. Primeiro, instala o pacote que lê esse arquivo. No terminal: npm install traço D dotenv. O traço D marca como ferramenta de desenvolvimento do projeto. [editor]
4. Na pasta do projeto, cria o arquivo ponto env. [menu]
5. Dentro: SAUCE underline USER igual standard user, e SAUCE underline PASSWORD igual secret sauce. [editor]
6. E antes de qualquer outra coisa: abre o ponto gitignore e escreve ponto env no final. Assim esse arquivo nunca vai pro GitHub. [editor]
7. No config, tira o comentário daquelas três linhas do dotenv. Elas mandam ler o arquivo ponto env. [editor]
8. No teste, troca o texto por process ponto env ponto SAUCE underline USER. [editor]
9. Traduzindo: process ponto env, as variáveis do ambiente. SAUCE underline USER, a variável com esse nome. [traducao]
10. E pra quem baixar o projeto saber o que preencher, cria um ponto env ponto example só com os nomes das variáveis, sem os valores. [editor]
11. Roda pra confirmar: continua passando. [editor]
12. Na próxima aula: rodando só o que importa. [passo]
13. Te vejo lá! [endcard]

## Aula 25: Rodando só o que importa - only, skip, arquivo e nome
1. Quando você tiver dezenas de testes, não vai querer rodar todos toda hora. [bigtext]
2. Pra rodar um arquivo só, coloca o nome dele: npx playwright test login ponto spec ponto js. [editor]
3. Pra rodar pelo nome do teste: traço g e um pedaço do nome, tipo bloqueado. O g vem de grep, que quer dizer procurar: ele filtra os testes por esse pedaço de nome. [editor]
4. Dentro do código, test ponto only: roda somente esse teste. Only quer dizer somente. [editor]
5. Cuidado: esquecer um only é um erro clássico. Os outros testes param de rodar e ninguém percebe. Por isso o config já vem com forbid only, que trava isso no GitHub. [cards]
6. E test ponto skip: pula esse teste. Skip quer dizer pular. No resultado, ele aparece como skipped. [editor]
7. E você já conhece o traço traço project igual chromium, pra rodar num navegador só. [cards]
8. Resumo de tudo numa tabela. [traducao]
9. Fechamos a organização. No próximo módulo: o que fazer quando o teste falha. [passo]
10. Te vejo lá! [endcard]
