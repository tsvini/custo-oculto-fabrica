## Aula 46: O que é uma API, explicado do zero
1. Quase todo site conversa com um servidor por trás. E pra essa conversa funcionar, existe a API. [bigtext]
2. Uma API é um jeito combinado de um sistema pedir dados ou ações pra outro. [cards]
3. Pensa num restaurante: você não entra na cozinha, você faz o pedido ao garçom, num formato combinado, e recebe a resposta. É uma simplificação, mas ajuda. [cards]
4. Um exemplo: quando você abre uma loja e aparecem os produtos, o site pediu a lista de produtos pra API, e a API respondeu. A tela só mostra o que veio. [cards]
5. Esses pedidos se chamam requisições, e cada uma tem um método. GET, buscar. POST, criar. DELETE, apagar. [traducao]
6. E a resposta vem com um número, o status: duzentos é deu certo, duzentos e um é criado, quatrocentos e quatro é não encontrado. E quinhentos é erro no servidor, que muitas vezes é bug. [cards]
7. Vamos usar uma API de treino gratuita, a jsonplaceholder. Abre no navegador o endereço dela, barra posts barra um. [tela_cheia]
8. Esse texto com chaves é JSON: um formato de dados que muitas APIs usam. [traducao]
9. E onde quem testa entra? Conferindo que cada pedido traz a resposta certa: o status certo, e os dados certos. [cards]
10. Na próxima aula: o seu primeiro teste de API. [passo]
11. Te vejo lá! [endcard]

## Aula 47: Seu primeiro teste de API
1. Teste de API não abre navegador nenhum. Por isso ele é bem rápido. [bigtext]
2. E por que testar a API, se dá pra testar pela tela? Porque se o servidor devolve o dado errado, a tela também mostra errado. Na API você acha o problema na origem, e em milissegundos. [cards]
3. Dentro da pasta tests, cria o api ponto spec ponto js. [menu]
4. No teste, em vez do page, você pede o request, entre chaves. [editor]
5. Request quer dizer requisição. [traducao]
6. const resposta igual await request ponto get, e o endereço. [editor]
7. Busque o post número um e guarde a resposta. [traducao]
8. expect, resposta ponto status, abre e fecha parênteses, to be duzentos. [editor]
9. Eu espero que o status da resposta seja duzentos. [traducao]
10. Repara nos parênteses depois do status. Status é uma ação: pergunta o status pra resposta. Sem os parênteses, não funciona. [editor]
11. Depois: const post igual await resposta ponto json, com parênteses. [editor]
12. Leia os dados que vieram. [traducao]
13. E a segunda conferência: post ponto id, to be um. Não basta dar certo: tem que vir o post certo. [editor]
14. Roda: passou, em milissegundos. [editor]
15. No dia a dia: conferir dados e regras, pela API, que é rápida. Pela tela, os caminhos que a pessoa faz, como o login e a compra. [traducao]
16. Na próxima aula: criando e apagando pela API. [passo]
17. Te vejo lá! [endcard]

## Aula 48: Criando e apagando dados pela API
1. Agora vamos simular uma criação e uma exclusão. A API de treino responde como uma de verdade, mas não guarda essas mudanças. [bigtext]
2. request ponto post, com um data: título, texto e userId. [editor]
3. É a requisição de criar. [traducao]
4. A conferência: status duzentos e um, criado. [editor]
5. E confere que o título que voltou é o mesmo que você mandou: a prova de que o servidor entendeu o pedido. [editor]
6. request ponto delete: apagar. Status duzentos. [editor]
7. Roda os três: passaram. [editor]
8. Num sistema real, essa criação e essa exclusão ficariam guardadas no banco de dados. [cards]
9. E tem um uso muito comum: preparar o terreno. Antes de um teste de tela, você cria pela API o que ele precisa, em milissegundos, em vez de clicar em dez telas. [compare]
10. Fechamos o bônus! Agora: desafios pra você praticar. [passo]
11. Te vejo lá! [endcard]
