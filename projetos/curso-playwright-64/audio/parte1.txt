Olha o teste da compra. Antes de testar qualquer coisa, ele monta as páginas: new Produtos Pêidji, new Tchécaut Pêidji. E isso se repete em todo arquivo que usa uma página. Agora repara no page. Você nunca escreveu new page: ele chega pronto, é só pedir entre chaves. Quem prepara é o próprio Playwright. Isso se chama fixture: alguma coisa que o teste recebe pronta. O page é uma, o request das aulas de êi-pí-ái é outra. E dá pra criar as suas. Na pasta do projeto, cria uma pasta nova chamada fixtures. E dentro dela, o arquivo paginas ponto jota éssi. Primeiro, os imports: o test do Playwright, e as duas páginas. Repara no test as base. Traduzindo: traga o test do Playwright, mas chame ele de base. Porque o nome test vai ficar pro nosso test novo, que a gente vai criar agora. Agora: export const test igual base ponto extend. Extend quer dizer estender: pegue o test original e acrescente coisas novas nele. Dentro, a receita do Lóguin Pêidji: ele recebe o page, cria um Lóguin Pêidji, e entrega pro teste com o use. Traduzindo: Lóguin Pêidji, o nome que o teste vai pedir. Entre chaves, o page, a fixture que já existe. E o use: entregue isto pronto pro teste. O Produtos Pêidji segue a mesma receita. E no fim, exporta o expect também, pra o teste importar tudo de um lugar só. Os testes do nível dois vão ficar numa pasta separada. Dentro de tests, cria uma pasta nova chamada nivel2. E dentro dela, o arquivo fixture ponto spec ponto jota éssi. Agora um teste usando a fixture. Primeira linha, o import: em vez de vir do Playwright, o test vem das suas fixtures. E no teste, você pede o Lóguin Pêidji entre chaves, igual ao page, e já usa. Antes, cada teste montava as páginas. Agora ele pede, e elas chegam prontas. O teste fica só com o que importa. Quando vale a pena? Quando as mesmas páginas aparecem em muitos testes, que é o caso de quase todo projeto grande. Num arquivo só, com um teste, o new na hora já resolve.
