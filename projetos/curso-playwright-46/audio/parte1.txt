Quase todo site conversa com um servidor por trás. E pra essa conversa funcionar, existe a API. Uma API é um jeito combinado de um sistema pedir dados ou ações pra outro. Pensa num restaurante: você não entra na cozinha, você faz o pedido ao garçom, num formato combinado, e recebe a resposta. É uma simplificação, mas ajuda. Um exemplo: quando você abre uma loja e aparecem os produtos, o site pediu a lista de produtos pra API, e a API respondeu. A tela só mostra o que veio. Esses pedidos se chamam requisições, e cada uma tem um método. GET, buscar. POST, criar. DELETE, apagar. E a resposta vem com um número, o status: duzentos é deu certo, duzentos e um é criado, quatrocentos e quatro é não encontrado. E quinhentos é erro no servidor, que muitas vezes é bug. Vamos usar uma API de treino gratuita, a jsonplaceholder. Abre no navegador o endereço dela, barra posts barra um. Esse texto com chaves é JSON: um formato de dados que muitas APIs usam. E onde quem testa entra? Conferindo que cada pedido traz a resposta certa: o status certo, e os dados certos. Na próxima aula: o seu primeiro teste de API. Te vejo lá!
