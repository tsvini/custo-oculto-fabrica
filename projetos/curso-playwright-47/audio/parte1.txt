Teste de API não abre navegador nenhum. Por isso ele é bem rápido. E por que testar a API, se dá pra testar pela tela? Porque se o servidor devolve o dado errado, a tela também mostra errado. Na API você acha o problema na origem, e em milissegundos. Cria o api ponto spec ponto js. No teste, em vez do page, você pede o request, entre chaves. Request quer dizer requisição. const resposta igual await request ponto get, e o endereço. Busque o post número um e guarde a resposta. expect, resposta ponto status, abre e fecha parênteses, to be duzentos. Eu espero que o status da resposta seja duzentos. Repara nos parênteses depois do status. Status é uma ação: pergunta o status pra resposta. Sem os parênteses, não funciona. Depois: const post igual await resposta ponto json, com parênteses. Leia os dados que vieram. E a segunda conferência: post ponto id, to be um. Não basta dar certo: tem que vir o post certo. Roda: passou, em milissegundos.
